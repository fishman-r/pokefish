# Pokefish 手机游戏版 UI 重构方案

版本：v0.4  
目标设备：iPhone 竖屏  
设计目标：把当前“可运行的功能面板”改成“以伙伴水域为核心的手机游戏界面”

## 一句话判断

现在的 UI 是一个能跑的 Godot 原型，但它的组织方式还是“后台/工具面板”。下一版必须把主场景、主伙伴、主操作放到第一层，把孵化、图鉴、远行、任务变成围绕主场景服务的游戏系统。

## 当前主要问题

1. 首页没有主角感  
   玩家一打开 App，先看到的是 Header、资源、导航和一串卡片，而不是水域、鱼群和可互动的伙伴。手机游戏应该先让玩家进入场景。

2. 导航位置不适合手机  
   当前模块导航在顶部，页面一滚动就离开视野。玩家切换模块需要回到顶部，操作成本高。竖屏游戏应采用底部固定 Tab 或右下角菜单。

3. 信息密度过高  
   资源、统计、鱼详情、进化、操作按钮都在同一条滚动流里，缺少主次。玩家不知道下一步最重要动作是什么。

4. 卡片堆叠过重  
   所有模块都使用相同粗边框卡片，视觉层级被抹平。主场景、操作区、列表项、标签都像同一种东西。

5. 触摸交互不够原生  
   现在通过全局 `_input` 补了滚动体验，但下拉框、按钮、鱼塘点击、弹窗后续容易互相抢事件。需要从界面结构上减少复杂滚动嵌套。

6. 文字承担了太多解释  
   当前很多文案是长句，靠自动换行兜底。手机游戏 UI 应该用短标签、数值、图标、状态条表达，而不是把规则解释都铺在主界面上。

7. 伙伴水域只是一个组件，不是主玩法  
   水域画布目前被放在卡片中间，更像装饰。下一版要让它成为首页背景和核心交互区。

8. 安全区和拇指区没有系统设计  
   顶部刘海、底部 Home Indicator、单手操作热区目前靠固定边距应付，不够稳。

## 新版产品原则

1. 首页即游戏场景  
   第一屏必须以水域和当前伙伴为视觉核心。

2. 固定 HUD，固定底部导航  
   顶部只放关键资源和玩家状态；底部长期保留五个模块入口。

3. 一个屏幕只做一件主事  
   首页负责收取、观察、投喂；孵化页负责孵化；图鉴页负责浏览；远行页负责派遣；任务页负责领取。

4. 复杂信息进入底部弹层  
   鱼详情、进化概率、基因、历史记录不要堆在首页长滚动里，改成底部 Sheet。

5. 少解释，多反馈  
   用动效、数值变化、短提示、徽章表达状态。详细规则放二级详情。

6. 视觉风格“原创怪兽收集”，避免官方宝可梦元素  
   参考掌机怪兽收集游戏的明亮色彩、粗描边、徽章、伙伴卡、图鉴感，但不使用任何宝可梦角色、Logo、球形标识或命名体系。

7. 主界面做文字减法  
   主界面只保留三类文字：名字、数值、动作。解释性文案、系统术语、规则描述、长状态句都进入二级弹层，或改为图标、徽章、进度条。

## 文字减法规则

1. 首页最多保留 8-12 个可读文字单元  
   包括水域名、伙伴名、资源数值、主按钮。不要在首页直接展示规则解释。

2. 导航优先图标化  
   底部 Tab 可以只让当前项显示文字，其余项用图标和选中态表达。若测试发现识别困难，再补短标签。

3. 状态优先进度条  
   心情、亲密、饥饿、进化概率等状态用颜色和条形表达。文字只保留必要数值，例如 `61%`。

4. 稀有度改成徽章  
   不在列表里反复写“稀有”“史诗”“传说”，改成 R、E、L 或颜色徽章。详情页可显示完整中文。

5. 解释进入详情  
   例如“水域、饲料、基因共同影响结果”不出现在主界面，只在进化详情或帮助面板展示。

6. 按钮文字压到 2-4 个字  
   主按钮可以保留 `收取`、`投喂`、`进化`。不要使用 `尝试进化`、`领取可用奖励` 这类生硬命令句。

## 信息架构

新版分为 5 个固定底部 Tab：

1. 水域  
   核心首页。展示水域、鱼群、当前伙伴、收取、投喂、进化入口。

2. 孵化  
   鱼蛋仓、孵化槽、饲料商店。重点是“获得新伙伴”。

3. 图鉴  
   已获得鱼群、物种收集进度、稀有度筛选、伙伴卡。

4. 远行  
   派遣当前伙伴或队伍去路线，领取回来奖励。

5. 目标  
   每日目标、长期成就、可领取奖励。

顶部固定 HUD：

- 左侧：玩家名或等级，如 `Lv. 7 驯养员`
- 中间：当前水域名
- 右侧：设置或菜单入口
- 第二行资源胶囊：泡泡币、贝壳、鱼蛋、珍珠

首页主区域：

- 70% 高度给水域场景
- 当前伙伴信息做成悬浮伙伴卡
- 右侧或下方放主操作按钮：收取、投喂、进化
- 不再把伙伴详情和进化实验室直接铺在首页下方

## 核心界面方案

### 1. 水域首页

目标：一眼看到“这是我的鱼塘，我的鱼在里面活着”。

布局：

- 顶部安全区内是固定 HUD
- 中央是全屏水域画布，背景不放进普通卡片
- 当前伙伴卡浮在水域底部左侧
- 资源产出气泡浮在水域右侧
- 主操作区固定在底部 Tab 上方
- 底部 Tab 固定

关键操作：

- 拖动任意空白区域滚动或移动视角
- 点击鱼：选中伙伴，显示小型状态浮层
- 点击伙伴卡：打开伙伴详情 Sheet
- 点击收取：播放资源飞入 HUD 的反馈
- 点击投喂：打开食物选择 Sheet
- 点击进化：打开进化确认 Sheet

### 2. 伙伴详情 Sheet

目标：把复杂信息收进一个可关闭的底部弹层。

内容：

- 伙伴头像/鱼体大图
- 名字、物种、稀有度、等级
- 心情、亲密、饥饿、产出四个状态条
- 基因与性格标签
- 最近一次进化故事
- 操作：设为看板、生成鱼卡、尝试进化

### 3. 孵化页

目标：像“获得新伙伴”的仪式，而不是商店列表。

布局：

- 顶部是孵化舱横向/纵向槽位
- 中部是当前鱼蛋库存和可孵化提示
- 底部是补给商店，使用短卡片

关键操作：

- 点击空孵化舱：选择鱼蛋
- 点击孵化：播放开蛋动画
- 孵化完成：弹出新伙伴获得卡

### 4. 图鉴页

目标：降低列表疲劳，突出收集进度。

布局：

- 顶部收集进度环或进度条
- 筛选：全部、普通、稀有、史诗、传说
- 鱼群列表改成两列小卡或紧凑列表
- 点击进入伙伴详情

### 5. 远行页

目标：像地图派遣，而不是任务清单。

布局：

- 上半部分是路线地图
- 路线点显示时间和奖励
- 下半部分显示推荐伙伴
- 已派遣状态显示倒计时和领取按钮

### 6. 目标页

目标：明确“现在能领什么”和“下一步做什么”。

布局：

- 可领取奖励置顶
- 每日目标列表紧凑显示
- 长期成就折叠在下方
- 完成项用强反馈，不用长文本解释

## 视觉系统

### 色彩

主色：

- 水域蓝：`#39B8F2`
- 深海墨蓝：`#102A48`
- 阳光黄：`#FFD94A`
- 活力绿：`#36C772`
- 珊瑚红：`#F95C52`

背景：

- 场景背景：浅天空蓝到水域蓝
- 普通面板：`#FFFFFF`
- 次级面板：`#F6FAFF`

描边：

- 主要描边：深海墨蓝，2-3 px
- 主按钮描边：深海墨蓝，3 px
- 列表项描边：1-2 px，降低压迫感

### 字体和字号

字体方向：

- 展示字体：`ZCOOL KuaiLe`
- 使用位置：标题、按钮、伙伴名、徽章、关键数值
- 气质目标：圆润、粗壮、像玩具包装和掌机游戏标题，而不是系统 App 面板
- 小标签字体：后续实现可继续使用更稳的圆体/黑体，避免 10-12 号小字变糊
- 不推荐：毛笔体、宋体、过度手写体、过窄科技字体

使用原则：

- 首页主按钮、伙伴名、模块标题必须换成游戏字体
- 小资源数值可以继续用清晰字体，但要做圆角胶囊和图标辅助
- 同一屏最多使用两种字体：展示字体 + 信息字体
- 如果全部文字都用展示字体，会可爱但容易累；如果全部文字都用系统字体，会像工具面板

- 页面标题：24-28
- 主数值：20-24
- 正文标签：13-16
- 底部 Tab：11-12
- 尽量避免 3 行以上正文出现在主界面
- 主界面尽量不出现完整说明句

### 组件

1. GameHUD  
   固定顶部玩家状态和资源。

2. BottomTabBar  
   固定底部五模块入口，带当前态。

3. PondStage  
   主水域场景，不再作为普通卡片处理。

4. PartnerChip  
   首页悬浮伙伴卡。

5. ActionDock  
   首页主操作区，最多 3 个主动作。

6. BottomSheet  
   伙伴详情、投喂、进化、获得新鱼都使用。

7. CompactCard  
   孵化、任务、路线、图鉴列表使用轻量卡片。

## Godot 实现计划

### 阶段 1：重构 UI Shell

目标：先把手机游戏骨架搭好。

任务：

- 新增固定 `hud_layer`
- 新增固定 `tab_layer`
- 中央 `screen_layer` 只渲染当前模块
- 移除当前把 Header、资源、导航、内容全塞进同一个 ScrollContainer 的结构
- 建立安全区常量：顶部、底部、左右边距
- 底部 Tab 不参与滚动

验收：

- 任意模块都能看到底部 Tab
- 切换模块不需要回到页面顶部
- 首页第一屏主要面积是水域

### 阶段 2：重做水域首页

任务：

- PondView 改为主场景层，宽高跟随可用屏幕
- 当前伙伴信息改成悬浮卡
- 收取、投喂、进化改成 ActionDock
- 点击鱼只改变当前伙伴，不直接改变页面结构
- 伙伴详情进入 BottomSheet

验收：

- 玩家打开 App 3 秒内能理解当前鱼、当前资源、当前可做动作
- 水域不再被多个卡片挤压

### 阶段 3：重做二级模块

任务：

- 孵化页：孵化槽 + 鱼蛋库存 + 补给商店
- 图鉴页：进度 + 筛选 + 鱼群卡
- 远行页：路线地图 + 派遣状态
- 目标页：可领取优先 + 紧凑任务列表

验收：

- 每个模块首屏只出现一个主任务
- 列表项不超过 2 行解释文字

### 阶段 4：组件化和主题化

任务：

- 抽出 `ui_theme.gd`
- 抽出 `ui_components.gd`
- 统一按钮、卡片、标签、进度条、底部弹层
- 减少 `_panel()` 滥用

验收：

- 主界面脚本不再承担大量样式细节
- 新增模块不需要重复写一套边框、颜色、字号

### 阶段 5：反馈和手感

任务：

- 收取资源飞行动画
- 切换 Tab 的轻动画
- 伙伴选中高亮
- 孵化获得新鱼弹层
- 进化成功/失败反馈
- 关键操作加轻微震动反馈，iOS 可后续接原生桥

验收：

- 玩家每次点击主操作都有明确反馈
- 成功和失败状态能被立即理解

## 推荐开发顺序

1. 先改 Shell：固定顶部 HUD + 固定底部 Tab
2. 再改水域首页：让首页看起来像游戏
3. 再做 BottomSheet：收纳复杂信息
4. 再改孵化、图鉴、远行、目标
5. 最后做动画和音效

不要先继续改颜色，也不要继续堆卡片。当前问题的根不是配色，而是信息架构。

## 验收清单

1. 打开 App 首屏，水域占据视觉主导。
2. 底部导航始终可见。
3. 首页不需要长滚动即可完成核心操作。
4. 伙伴详情、投喂、进化通过底部弹层完成。
5. 每个模块首屏只有一个明确主任务。
6. 长文案明显减少，主界面以名字、数值、动作和图标为主。
7. iPhone 刘海区和 Home Indicator 不遮挡关键按钮。
8. 单手拇指能触达主要操作。
9. 切换模块没有遮挡、重叠或滚动残留。
10. UI 风格原创，不依赖宝可梦官方视觉资产。
11. 首页没有规则说明句，复杂规则只在二级详情中出现。

## 预计工作量

保守估计：

- Shell 重构：0.5-1 天
- 首页重构：1-1.5 天
- BottomSheet 和伙伴详情：0.5-1 天
- 四个二级模块重构：1.5-2.5 天
- 动效和真机调优：1 天

总计约 4.5-7 天。  
如果先做一个可体验的新版首页 Demo，可以压缩到 1-2 天。
