# Pokefish UI v2 优化方案与子任务

更新时间：2026-06-06 19:44（Asia/Shanghai）

依据：`godot/build/qa_snapshots/01_home.png` 到 `09_debug_overlay.png` 的最新截图，以及首轮 iPhone 手测记录。

## 结论

当前 UI 已经能用，也已经具备 Godot App 的基本结构，但还没有真正达到“成熟手机游戏”的观感。最大问题不是单个按钮或颜色，而是整体仍然像“可爱皮肤的工具型界面”：

- 首页底部控件过重，鱼和水域不是绝对主角。
- HUD、伙伴卡、按钮、面板都使用相近的粗描边卡片，层级过平。
- 二级模块仍像表单和列表，不像孵化所、图鉴册、远行地图、任务板。
- 远行面板仍存在文字竖排/裁切硬伤，说明文本布局 QA 需要继续加强。
- 图标和文字在“减少文字”和“可理解”之间还没有找到稳定平衡。

v2 优化不应该继续小修圆角和颜色，而应该重做 UI 架构的视觉层级。

## v2 设计目标

1. 首页第一眼必须是“活的水域”，不是 HUD 和底部工具栏。
2. 常驻 UI 只保留高频操作，低频模块入口收进轻量菜单或地图式入口。
3. 二级模块不再复用同一种卡片列表，而是按游戏场景分别设计。
4. 字体、描边、阴影、颜色建立主次层级，避免所有元素都很响。
5. 自动 QA 必须覆盖文字竖排、控件越界、底部遮挡和截图视觉面积。

## 不继续做的方向

- 不再把所有功能都堆在底部两排 Dock。
- 不再让所有信息都用圆角卡片承载。
- 不再为了减少文字把入口做成难懂纯图标。
- 不再用列表页思路处理孵化、图鉴、远行和目标。
- 不再仅以 headless 布局通过作为“视觉可接受”的判断。

## 优先级总览

| 优先级 | 目标 | 必须解决的问题 |
|---|---|---|
| P0 | 硬伤修复 | 远行文字竖排、裁切、文本 QA 不足 |
| P1 | 首页重构 | 底部过重、HUD 抢戏、水域存在感不足 |
| P2 | 导航重构 | 主动作和模块入口混在一起、视觉权重接近 |
| P3 | 模块游戏化 | 孵化/图鉴/远行/目标仍像表单列表 |
| P4 | 视觉系统 | 描边、颜色、字体、图标层级不清 |
| P5 | 动效和 QA | 游戏反馈不足、视觉回归缺少硬约束 |

## 子任务拆解

### P0：修复文字和布局硬伤

#### T0.1 修复远行面板文字竖排

问题：`07_adventure.png` 中远行面板左侧出现竖排文字和裁切，是当前最明显硬伤。

建议实现：

- 检查 `AdventureMap` 中路线卡、标题、描述、奖励行的最小宽度。
- 禁止短文本容器被压到只剩一列字宽。
- 为路线卡设置稳定宽度和横向布局，不允许 CTA 挤压路线名称。
- 当空间不足时优先隐藏低价值描述，而不是压缩文字。

涉及文件：

- `godot/scripts/ui/adventure_map.gd`
- `godot/scripts/ui/panel_host.gd`
- `godot/scripts/qa/text_render_audit.gd`
- `godot/scripts/qa/visual_snapshot_audit.gd`

验收：

- `07_adventure.png` 中无竖排中文。
- 远行路线名、时间、奖励、按钮均完整或合理省略。
- `text_render_audit.gd` 增加断言：短中文标签不得超过 2 行，不得出现高度远大于宽度的文本盒。

#### T0.2 建立“竖排文字”通用 QA

问题：之前多个页面都出现过短文本被挤成竖排，说明这不是单点问题。

建议实现：

- 遍历所有可见 `Label`，对 2 到 12 字的短文本检查宽高比。
- 对按钮、标签、资源徽章、任务标题分别设置最低可用宽度。
- 在视觉截图 QA 后增加截图级别的“异常窄文字区域”提示。

涉及文件：

- `godot/scripts/qa/text_render_audit.gd`
- `godot/scripts/qa/visual_snapshot_audit.gd`
- `godot/scripts/ui/ui_components.gd`

验收：

- 9 张视觉快照都无短文本竖排。
- QA 能在远行这种问题复发时失败，而不是仅靠肉眼发现。

### P1：首页重构

#### T1.1 缩小顶部 HUD，让水域先被看到

问题：首页顶部 HUD 面积和描边太重，第一眼像状态面板。

建议实现：

- 顶部 HUD 从大卡片改成两块轻量区域：左侧等级/池塘名，右侧资源胶囊。
- 隐藏低频资源，只保留主资源和一个展开入口。
- 减少 HUD 背景透明白面积，降低描边强度。

涉及文件：

- `godot/scripts/ui/resource_hud.gd`
- `godot/scripts/ui/ui_style.gd`
- `godot/scripts/qa/layout_audit.gd`

验收：

- 390x844 首页中顶部 HUD 高度建议不超过 76px。
- 首页可见水域面积明显大于 UI 面积。
- 资源仍可读，菜单入口仍不小于 44px。

#### T1.2 重做伙伴信息，从“卡片”改成“场景态”

问题：伙伴浮标像一张业务卡片，占据底部水域空间，并和主动作 Dock 竞争。

建议实现：

- 选中鱼时，在鱼附近显示轻量名字牌、等级和心情条。
- 未选中时，只保留当前伙伴的小头像/状态徽章。
- 伙伴详情通过点击鱼或头像打开，不常驻大卡。

涉及文件：

- `godot/scripts/ui/partner_float.gd`
- `godot/scripts/ui/pond_view.gd`
- `godot/scripts/ui/main_game.gd`
- `godot/scripts/ui/bottom_sheet.gd`

验收：

- 首页底部不再同时出现伙伴大卡和两排 Dock。
- 选中状态清晰，点击鱼后能打开伙伴详情。
- 伙伴信息不遮挡鱼和主动作按钮。

#### T1.3 增强水域场景主角感

问题：水域中间大面积空白，底部环境素材被 Dock 遮挡，游戏世界感不足。

建议实现：

- 将环境素材分为远景、中景、前景三层，前景避开底部按钮。
- 增加轻量泡泡、波纹、鱼影和资源泡泡，但控制节点预算。
- 选中鱼时增加描边、光圈或水波反馈。

涉及文件：

- `godot/scripts/ui/pond_view.gd`
- `godot/scripts/ui/pond_stage.gd`
- `godot/scripts/qa/performance_budget_audit.gd`
- `godot/scripts/qa/visual_snapshot_audit.gd`

验收：

- 首页第一眼焦点落在鱼和水域。
- 底部环境素材不被 Dock 大面积遮挡。
- 性能 QA 仍通过，节点峰值不持续增长。

### P2：底部导航和主动作重构

#### T2.1 拆分“主动作”和“模块入口”

问题：现在三枚主动作和五枚模块入口权重接近，底部像工具栏。

建议实现：

- 首页常驻只保留三枚主动作：投喂、收取、进化。
- 模块入口收进一个“口袋菜单”按钮，打开半屏功能盘。
- 高频模块可在菜单里保持 2 字短标签和大图标，不常驻压首页。

涉及文件：

- `godot/scripts/ui/action_dock.gd`
- `godot/scripts/ui/mode_dock.gd`
- 新增 `godot/scripts/ui/module_menu.gd`
- `godot/scripts/ui/main_game.gd`

验收：

- 首页底部常驻 UI 从两排减为一排主动作 + 一个轻量菜单入口。
- 模块切换不超过 2 次点击。
- 单个触控目标不小于 56px，高频动作不小于 64px。

#### T2.2 建立主动作视觉等级

问题：投喂、收取、进化目前像三个同级彩色按钮，缺少当前语境。

建议实现：

- 收取在有收益时成为最强按钮，无收益时降低饱和度。
- 投喂只有选中鱼时强调，否则提示先选鱼。
- 进化在可进化时发光，不可进化时收敛成次级状态。

涉及文件：

- `godot/scripts/ui/action_dock.gd`
- `godot/scripts/ui/game_state_controller.gd`
- `godot/scripts/ui/main_game.gd`

验收：

- 玩家不用读文字也能知道当前最该点哪个动作。
- 禁用和可用状态视觉差异明确。
- 主动作按钮不再全部同时“很响”。

- 世界物体和主按钮可用 3px 描边。
- 二级卡片使用 2px 描边。
- 小标签和资源胶囊使用 0-1px 描边或无描边。
- 阴影只用于浮层和主按钮，列表项减少阴影。

涉及文件：

- `godot/scripts/ui/ui_style.gd`
- `godot/scripts/ui/ui_components.gd`

验收：

- 首页不再所有元素同等抢眼。
- 弹层内列表项比弹层容器更轻。
- 视觉快照中主次层级更清楚。

#### T4.2 重定义颜色语义

问题：黄色同时表示选中、投喂、领取、孵化，语义混乱。

建议实现：

- 黄色：当前选中/奖励领取。
- 绿色：成功/成长/可进化。
- 蓝色：水域/收取/资源。
- 橙色：消耗/稀有材料/蛋。
- 灰白：不可用/未知/次要。

涉及文件：

- `godot/scripts/ui/ui_style.gd`
- 所有使用 `UiStyle.YELLOW/GREEN/ORANGE/WATER` 的 UI 脚本

验收：

- 同类行为颜色一致。
- 主要 CTA 每个页面最多一个。
- 不再满屏多个同强度黄色按钮。

#### T4.3 重做图标语言

问题：很多图标都是“圆形容器里小符号”，差异不够强。

建议实现：

- 主动作图标使用大形状：食碗、泡泡袋、星光鱼。
- 模块图标使用外形差异：蛋、书、地图、印章。
- 资源图标保留小圆徽章，但不和功能入口图标同一套路。

涉及文件：

- `godot/scripts/ui/ui_components.gd`
- `godot/scripts/ui/action_dock.gd`
- 新增或调整模块菜单图标

验收：

- 关闭文字时也能大致区分主动作。
- 打开文字时不会显得重复解释。
- 图标不再全部像同一种圆章。

### P5：动效、交互和 QA 收口

#### T5.1 添加场景化动效

目标：让 Godot 的能力真正进入体验，而不是只做静态 UI。

建议实现：

- 首页水面轻微波动、泡泡上升。
- 点击鱼有水波和鱼的短反馈。
- 收取泡泡飞入 HUD。
- 投喂食物从 Dock 抛入水中。
- 进化时短暂聚光和闪白，但不影响性能。

涉及文件：

- `godot/scripts/ui/pond_view.gd`
- `godot/scripts/ui/main_game.gd`
- `godot/scripts/qa/performance_budget_audit.gd`

验收：

- 交互反馈比静态按钮更像游戏。
- 低端预算仍安全，特效结束后节点清理。

#### T5.2 增强视觉 QA

目标：避免“自动化全绿但肉眼明显不舒服”。

建议实现：

- 增加首页 UI 占屏面积审计：常驻 UI 不应压过水域主体。
- 增加底部双 Dock 禁止项：v2 首页不允许两排常驻导航。
- 增加模块截图检查点：远行无竖排、图鉴卡不外溢、目标卡不压底。
- 保存 v2 视觉基准截图。

涉及文件：

- `godot/scripts/qa/layout_audit.gd`
- `godot/scripts/qa/text_render_audit.gd`
- `godot/scripts/qa/visual_snapshot_audit.gd`
- `docs/qa/iphone-hand-test-checklist.md`

验收：

- `run_all_qa.sh` 能发现主要视觉回归。
- 手测清单改为 v2 重点项：水域主角感、底部轻量、模块像游戏场景、长时间手感。

## 推荐执行顺序

## v2 完成判定

必须同时满足：

1. 9 张视觉快照无竖排文字、无明显裁切、无模块溢出。
2. 首页常驻底部 UI 不再是两排工具栏。
3. 首页第一眼焦点在鱼和水域，而不是 HUD/Dock。
4. 孵化、图鉴、远行、目标至少各有一个明确游戏隐喻。
5. iPhone 手持复测中，内容拖拽、图标理解、单手操作、长时间手感均为通过或仅轻微需调整。
6. `POKEFISH_SKIP_DEVICE_QA=1 godot/scripts/qa/run_all_qa.sh` 通过。
7. `godot/scripts/qa/ios_debug_deploy.sh` 通过并能在 iPhone 上启动。

## 取舍建议

如果时间有限，优先做：

1. 修远行文字硬伤。
2. 首页底部从双 Dock 改成单主动作 Dock。
3. 远行改成小地图。
4. 缩小 HUD。

这四项会最明显地改变“工具型 App”的观感。

如果继续追求完整品质，再做孵化台、图鉴册、任务板和动效系统。
